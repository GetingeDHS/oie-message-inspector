# Message Inspector

OIE (Open Integration Engine / Mirth Connect) extension that adds HL7v2 message inspection with tree view, field descriptions, validation, and table lookups.

## Build & Test

```bash
mvn clean package
```

The ZIP lands in `message-inspector-plugin/target/` — extract into OIE `extensions/` directory and restart server.

There are no unit tests yet. Test manually by installing the extension and parsing HL7 messages in the Web Client.

## Key Conventions

- **Language**: All code, UI labels, comments in English
- **Package**: `com.oie.messageinspector` (community-neutral, NOT Getinge namespace)
- **Plugin name**: "Message Inspector", author "Getinge IT Solutions GmbH"
- **License**: MPL-2.0 (compatible with CC BY 4.0 and CC0 data files)
- **License header**: Every source file starts with a license block. Copyright stays with the contributor.
  ```java
  /*

   * Copyright (c) 2026 Getinge IT Solutions GmbH
   */
  ```
- **DCO**: All commits require `Signed-off-by` (enforced by CI). See CONTRIBUTING.md.
- **Java**: 17, all OIE/Mirth dependencies as `provided` scope
- **Frontend**: Single JSX file (`plugin.jsx`), bundled via esbuild to `plugin.js`. Uses `platform.React` from `@oie/web-shell` — no npm React dependency. Must rebuild after every JSX change.

## OIE-Specific Patterns

- **Supported OIE versions**: `oie.compatibleVersions` in the parent POM feeds `<mirthVersion>` in `plugin.xml`. OIE strips the build number from its own version and compares major.minor.patch exactly against each comma-separated entry, so every patch release (e.g. 4.7.1) must be listed explicitly. Update README "Installation" when changing it.

- **XStream JSON wrapping**: OIE's MirthServlet wraps every POJO in its Java class name. Frontend has `unwrap()` to strip these wrappers. Use plain `ArrayList` in responses (not `Collections.unmodifiableList()` which XStream can't serialize).
- **API headers**: All `fetch()` calls to `/api/` endpoints MUST include `'X-Requested-With': 'XMLHttpRequest'` header or the server returns HTTP 400.
- **HL7v2 Vocabulary**: `HL7v2Vocabulary` is on the OIE server classpath but not a compile-time dependency — accessed via reflection in `InspectorServlet`.
- **HAPI v2.3**: Structure JARs only cover v2.1–v2.6. For v2.5.1, v2.7+, HAPI uses `GenericMessage` where all fields are `Varies` type — must `unwrapVaries()` before accessing components.

## HL7 Reference Data

Three JSON files provide HL7 standard metadata:

| File | Size | Source | License | Loading |
|------|------|--------|---------|---------|
| `hl7-tables.json` | ~1 MB | HL7 THO v6.3.0 | CC0-1.0 | Eager (server start) |
| `hl7-segment-definitions.json` | ~2.7 MB | HL7 v2.x Access DB | CC BY 4.0 | Eager (server start) |
| `hl7-field-descriptions.json` | ~5.9 MB | HL7 v2.x Access DB | CC BY 4.0 | Lazy (first request) |

Segment defs cover v2.1–v2.9. Field descriptions only available v2.5–v2.9 (older versions lack chapter paragraphs in the DB).

## RBAC

- Single permission `accessInspector` registered in `MessageInspectorServicePlugin.getExtensionPermissions()`
- All three endpoints (`/check`, `/parse`, `/field-description`) gated via `@MirthOperation(permission = "accessInspector")`
- `GET /check` is a lightweight access probe — returns 200 if authorized, 403 if not
- `register()` in `plugin.jsx` fetches `/check` before registering the tab; unauthorized users never see the nav item
- The Diridium RBAC plugin automatically picks up the permission in its role editor

## Data Flow

1. On page load, `register()` fetches `GET /api/extensions/message-inspector/check` — if 403, tab stays hidden
2. User pastes HL7 message into textarea (auto-parses after 500ms debounce)
3. `POST /api/extensions/message-inspector/parse` → `InspectorParseEngine` parses with HAPI, enriches with `HL7SegmentDefs` and validates
4. Returns `InspectorParseResult` JSON with tree of segments → fields → components/repetitions
5. Frontend renders tree (with search/filter), detail panel, table values, validation issues
6. Clicking a tree node highlights the corresponding text range in the raw message textarea
7. On field click, frontend fetches detailed description via `GET /api/extensions/message-inspector/field-description`
8. Message Browser integration: `platform.registerMessageAction()` adds "Inspect Message" action to any message

## Field Resolution Priority

For field names, optionality, data types, and table bindings:
1. `HL7SegmentDefs` (reference data from HL7 Access DB) — primary
2. HAPI structural metadata (`isRequired`, `getField`, structure classes) — fallback
3. `HL7v2Vocabulary` (OIE's built-in vocabulary via reflection) — last resort for descriptions
